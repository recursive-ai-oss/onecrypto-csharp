# Key-backend glue review

An internal review of the glue between OneCrypto's operations and keys that live elsewhere: the PKCS #11 backend (`OneCrypto.Keys/Pkcs11`), the gpg-agent and ssh-agent clients (`OneCrypto.Keys/Agents`), the CSC remote-signing client (`OneCrypto.Online/Csc`), the core key interfaces and two-phase signing state (`OneCrypto/Keys`), the OpenPGP external-key path (`PgpSecretKey.FromExternalKey`, `PgpReadOptions.ExternalKeys`, `Messages/SessionKeys.cs`, `Messages/MessageReader.cs`) and CMS use of external keys (`Cms/CmsRecipients.cs`). **This is an internal review by an engineer who did not write the code. It is not an external audit; the library is not independently audited.**

Method: the code was read against the PKCS #11 v3.1 text, the Assuan manual, the ssh-agent draft, the CSC API v2.2 and RFCs 7748, 8017 and 9580; hostile peers were built as test doubles (a native-callable function table that plays a module, scripted keys, byte mutation of serialised states). Every finding below has a regression test; settled behaviour needed no oracle. Tests: `tests/OneCrypto.Keys.Tests/HostilePkcs11ModuleTests.cs`, `KeyBackendGlueTests.cs`, `Pkcs11PgpTests.ATamperedSessionKeyPacketIsTheSameFailureThroughTheToken`, `tests/OneCrypto.Tests/Keys/PreparedSignatureTamperTests.cs`, `tests/OneCrypto.OpenPgp.Tests/KeyManagementTests.EveryTruncationAndOctetChangeOfAPgpState…`.

## Not fixed (follow-ups)

- **F1** `PgpSecretKey.FromExternalKey` does not compare the external key's public key with the OpenPGP key packet. The backends now verify against their own public key, so a mismatched pair signs correctly for the wrong key and the OpenPGP signature fails at the verifier. Low; the caller owns the pairing (documented).
- **F2** Where the platform cannot verify the scheme at all (`AlgorithmNotSupported`: Brainpool on macOS, ML-DSA without platform support) agents and tokens release the signature unchecked. Accepted as the narrow gap of the platform table; a strict option could refuse.
- **F3** CSC authentication values (`CscAuthObject`) and tokens are .NET strings: they are redacted in every `ToString`, error and recording, but cannot be zeroed. PKCS #11 PINs are copied into pinned buffers and zeroed.
- **F4** A call into a module that waits for a PIN pad holds the module-wide gate; the synchronous API has no cancellation, so other sessions of that module wait. Not documented yet.
- **F5** The key interfaces do not apply `CryptoPolicy`: calling a token or CSC key directly with a SHA-1 digest signs it, as an in-memory key does. Policy is enforced where the operation is: `PreparedSignature.Prepare`, CMS `SignerPlan`, OpenPGP `SignatureBuilder`, the X.509 builders. By design.
- **F6** A hostile agent's malformed reply during decryption (`AgentProtocolException`) is not folded into the plain failure; it is a protocol fault, not a property of the message.

## What was checked and found sound

- **Assuan:** command lines are one line (CR/LF refused) and ≤ 1000 octets; keygrips are validated as 40 hex digits before they are put in a command; descriptions are percent-escaped; replies are bounded (line 1100, reply total), data buffers wipe on growth, S-expressions are bounded in depth (8) and nodes (256); inquiries we cannot answer are cancelled. Tested in `HostileAgentTests` (18 cases).
- **ssh-agent:** reply length is checked before allocation (default 256 KiB), the key count is bounded by what the reply can hold, the reply type must be the expected one, the returned signature must be the algorithm asked for and is verified against the public key; `ssh-rsa` (SHA-1) is never requested.
- **gpg-agent:** signatures verified by default; a refusal that is not a cancel, bad passphrase or pinentry error becomes the plain decryption failure; agent plaintext is wiped after use; the Montgomery key refuses an all-zero result; EdDSA message size is limited with a typed error.
- **CSC:** the digest always goes to `credentials/authorize` (the SAD is bound to it), no redirect is followed, the signature count must equal the digest count, every returned signature is normalised and verified against the credential's certificate key before release, tokens and SADs are redacted in `ToString`, errors and recordings (`CscClientTests`, `CscGuardTests`, `CscFixtureTests`).
- **Two-phase state:** versioned, purpose-labelled (TSA, OCSP, CMS and X.509 flows check the label), carries only public data (key, digest or message, spec), refuses a digest that does not match its data, a scheme that does not fit its key, and a signature from another key, over other data or in another encoding. Truncation and single-octet changes end in a typed refusal (K7, K8).
- **Resources:** PKCS #11 sessions close once under the module gate and unregister; key objects hold nothing to release; derived-secret objects are destroyed in a `finally`; the agent clients use one connection per operation, closed on every path including cancellation (`AnAgentThatNeverAnswersIsCutOffByTheOperationTimeout`).
- **PKCS #11:** `CKA_ALWAYS_AUTHENTICATE` keys are refused; PINs are converted into pinned buffers and zeroed; `Pkcs11PinException` messages carry the token's result code only.

## Timing targets to re-run

None of the changed code handles a secret by branching on its value. For completeness, the OpenPGP session-key glue (`SessionKeys.cs`: the exception filter, the all-zero check over the shared secret, which is a fixed pass with a single test of the OR) is the only secret-adjacent edit; the existing session-key glue target covers it.
